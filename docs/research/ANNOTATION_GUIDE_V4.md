# Инструкция по разметке отзывов v4

Статус: каноническая инструкция для всех новых review-level разметок после 20 октября 2026 года.

## 1. Что видит разметчик

Разметчик использует только:

- текст отзыва;
- заказанный размер, если он сохранён в строке.

Нельзя открывать карточку товара, смотреть сигналы маркетплейса, прогноз модели или ответы другого разметчика. Не нужно угадывать обычный размер покупателя, если он не указан.

### Названия полей

Во всех таблицах, которые заполняет человек, используются русские заголовки и русские значения справочников, как в двух исходных файлах ручной разметки. Английские ключи `snake_case` используются только во внутренних `JSONL`, конфигурациях, нормализованных датасетах и коде.

| Поле ручной таблицы | Внутренний ключ |
|---|---|
| `review_id` | `review_id` |
| `заказанный размер` | `ordered_size` |
| `текст отзыва` | `review_text` |
| `метка посадки` | `fit_label` |
| `код метки` | `fit_code` |
| `явность сигнала` | `signal_explicitness` |
| `параметры тела 1–3` | `body_parameters` |
| `зона посадки 1–3` | `fit_zones` |
| `действие пользователя` | `user_action` |
| `согласованность внутри отзыва` | `internal_consistency` |
| `информативность` | `informativeness` |
| `комментарий` | `annotator_comment` |

Для метки посадки в ручной таблице используются значения `маломерит`, `соответствует`, `большемерит`, `нет сигнала`. Они однозначно преобразуются во внутренние `runs_small`, `true_to_size`, `runs_large`, `no_signal`. Для явности сохраняются значения `explicit`, `implicit`, `none`, поскольку именно они использовались в обоих исходных файлах разметчиков.

Поле `код метки` в XLSX заполняется формулой автоматически после выбора `метки посадки`: `маломерит = -1`, `соответствует = 0`, `большемерит = 1`, для `нет сигнала` ячейка остаётся пустой. Разметчик не редактирует эту колонку вручную.

## 2. Порядок разметки

Поля заполняются строго по порядку:

1. `fit_label`;
2. `signal_explicitness`;
3. параметры тела и зоны посадки;
4. действие пользователя;
5. внутренняя согласованность;
6. информативность.

Сначала определяется направление размерного соответствия. Остальные поля не должны превращать неясный отзыв в направленный fit-сигнал.

## 3. Fit-класс

| Метка | Когда ставить |
|---|---|
| `runs_small` | прямо сказано «маломерит» либо явно показано, что для нормальной посадки нужен размер больше обычного |
| `true_to_size` | прямо сказано «размер в размер»/«соответствует размеру» либо явно совпадают обычный и заказанный размеры |
| `runs_large` | прямо сказано «большемерит» либо явно показано, что для нормальной посадки нужен размер меньше обычного |
| `no_signal` | направление относительно размерной сетки или обычного размера установить нельзя |

### Обязательная граница `no_signal`

Фразы «сел идеально», «подошло», «сидит хорошо», «тесно», «свободно», «велико» или «мало» сами по себе не доказывают систематическое направление размерной сетки. Без обычного размера, прямой формулировки или однозначного сравнения ставится `no_signal`.

Также ставится `no_signal`, если:

- больший размер выбран ради oversize или личного предпочтения;
- меньший размер выбран ради более облегающей посадки;
- проблема относится только к росту или длине изделия;
- покупатель пишет, что сам ошибся с размером, но не называет обычный размер;
- направление зависит только от конкретной зоны или особенностей фигуры и нельзя сделать общий вывод о размерной сетке.

## 4. Явность сигнала

- `explicit`: направление названо прямо — «маломерит», «размер в размер», «большемерит» или равнозначной фразой.
- `implicit`: направление однозначно следует из сравнения обычного и заказанного размера, но не названо напрямую.
- `none`: обязательное значение при `fit_label = no_signal`.

Нельзя ставить `explicit` только потому, что фраза эмоциональная или уверенная.

## 5. Параметры тела

Отмечаются только прямо названные параметры:

- `height` — рост;
- `bust` — грудь или ОГ;
- `waist` — талия или ОТ;
- `hips` — бёдра или ОБ;
- `other` — другой явно указанный параметр.

Можно выбрать до трёх разных значений. Размер одежды сам по себе не является параметром тела.

## 6. Зоны посадки

Допустимые зоны: `bust`, `waist`, `hips`, `shoulders`, `sleeves`, `length`, `other`.

Зона отмечается, только если текст сообщает о посадке именно в этой части изделия. Упоминание детали без fit-информации не считается зоной посадки.

## 7. Действие пользователя

| Метка | Правило |
|---|---|
| `not_specified` | действие не указано |
| `kept_ordered_size` | прямо сказано, что товар оставили, забрали, выкупили или носят |
| `chose_another_size` | выбран другой размер |
| `exchanged` | прямо указан обмен |
| `returned` | прямо указан возврат или отказ |
| `ordered_multiple_sizes` | заказано несколько размеров для выбора |
| `other` | другое явное действие |

Положительный отзыв, рекомендация или фраза «подошло» не означают `kept_ordered_size` без явного действия.

## 8. Внутренняя согласованность

- `consistent`: все пригодные направленные сигналы совпадают.
- `contradictory`: пригодные сигналы указывают в разные стороны и конфликт нельзя объяснить разными зонами посадки.
- `unclear`: направленного сигнала нет либо согласованность нельзя оценить.

При `fit_label = no_signal` обычно ставится `unclear`.

## 9. Информативность

Информативность оценивает только доказательность fit-вывода, а не грамотность, длину или эмоциональность текста.

| Метка | Критерий |
|---|---|
| `low` | направления нет либо есть только голое утверждение без подтверждения |
| `medium` | есть один независимый подтверждающий элемент: параметр тела, зона посадки, действие из-за посадки или сравнение размеров |
| `high` | есть явное сравнение обычного и заказанного размера либо минимум два независимых подтверждающих элемента |

Повтор одного факта другими словами не увеличивает уровень.

## 10. Пограничные примеры

| Текст | Итог |
|---|---|
| «Сели идеально, качество отличное» | `no_signal`, `none`, `low` |
| «Маломерит» | `runs_small`, `explicit`, `low` |
| «На свой 44 взяла 46, после этого подошло» | `runs_small`, `implicit`, `high` |
| «На свой 44 взяла 46, люблю свободный oversize» | `no_signal`, `none`, `low` |
| «Идут размер в размер, но для облегания можно взять меньше» | `true_to_size`, `explicit`; возможность другой стилизации не меняет класс |
| «На рост 180 короткие» | общий fit-класс `no_signal`; зона `length`, параметр `height` |
| «В талии свободно, в бёдрах тесно» | без обычного размера — `no_signal`; зоны `waist` и `hips`; consistency `unclear` |

## 11. Контроль перед сдачей

- Для `no_signal` указаны `fit_code = null` и `signal_explicitness = none`.
- Значения не придуманы по карточке товара или размерной сетке.
- Параметры тела и зоны не дублируются.
- `kept_ordered_size` основан на явном действии.
- `high` объясняется сравнением размеров или двумя независимыми подтверждениями.
- Сомнительный случай отмечен комментарием, но все обязательные поля заполнены.

Для новой команды сначала независимо размечается калибровочная партия 100–150 отзывов. Расхождения разбираются до основной партии, после чего инструкция не меняется до завершения текущего snapshot.
