# Оценки подборок и сервиса

После каждой завершённой непустой подборки доступны два независимых вопроса:
- соответствие образов запросу, 1–10;
- общая удовлетворённость AI StyleLink, 1–10.

Оба вопроса доступны с первой подборки, комментарий необязателен (до 2000 символов).
Оценка подборки хранится отдельно для каждой генерации. Общая оценка сервиса одна
на пользователя, её можно изменить. Повторная отправка обновляет оценку, а история
ответов остаётся в feedback_events. Опрос о посадке и возвратах не изменён.

При просмотре третьей или более поздней успешной генерации, если общей оценки ещё
нет, через 12 секунд в активной вкладке появляется одно приглашение. Пока открыт
другой диалог или пользователь вводит текст/выбирает размер, показ откладывается.
Счётчик серверный, за всё время; ошибки и результаты без образов исключены.
После закрытия приглашение больше не показывается; общий вопрос остаётся под
каждой подборкой. Состояние хранится в БД и действует между сессиями/устройствами.

## Перед запуском

Из backend выполнить alembic upgrade head. Новая миграция b8c9d0e1f2a3.
Frontend и backend обновляются вместе. Внешних рассылок или отправки данных
сторонним сервисам нет.

## Данные и анализ

feedback_ratings: актуальные оценки; feedback_prompts: однократное приглашение;
feedback_events: фактическая видимость заголовка вопроса (не менее половины в
активной вкладке), приглашение, закрытие, первый ответ и изменения.
Контекст содержит generation_id, номер успешной генерации, A/B-группу, страту,
версию анкеты, источник inline/invitation и серверное время.
Показы inline дедуплицируются по пользователю, генерации и вопросу.

Для гипотезы «удовлетворённость первого опыта» брать первый rating_submitted
со scope=service и generation_number=1. Для общей текущей оценки использовать
feedback_ratings scope=service (одна запись на пользователя). Не смешивать
оценки подборок и сервиса, первый и повторный опыт; отдельно показывать число
ответов и охват вопросом. События клиента могут не сохраниться при обрыве сети,
поэтому охват не следует считать гарантированно полным.


## Структура реализации

Backend следует принятому разделению: app/api/v1/feedback.py отвечает за HTTP,
авторизацию и завершение транзакции; app/services/feedback_service.py — за правила
сохранения, условия приглашения и события; app/schemas/feedback.py — за проверку
запросов и типы ответов; app/models/feedback.py — за таблицы.

Frontend находится в features/feedback: api, types, configurations, hooks и
components. RatingForm используется и под подборкой, и в приглашении.
useGenerationFeedback управляет загрузкой, сохранением и отложенным приглашением.

## Как проверить при ревью

1. Открыть первую успешную подборку: оба вопроса доступны без покупки и возврата.
2. Оценить подборку, перезагрузить страницу, изменить ответ: запись обновляется,
   а история сохраняет прежний ответ.
3. На новом аккаунте оценить сервис после первого подбора: после третьего
   приглашение не появляется.
4. На другом аккаунте оценивать только подборки: после просмотра третьей успешной
   генерации через 12 секунд появляется приглашение оценить сервис.
5. Закрыть приглашение и открыть результаты снова: автоматического повтора нет,
   но общий вопрос под подборкой остаётся.
6. При ошибке сохранения ответ остаётся в форме, доступна повторная отправка.

Автоматические проверки: из backend запустить
python -m pytest tests/test_feedback.py tests/test_feedback_migration.py tests/test_research_contract.py.
Из frontend — npm run build; eslint для features/feedback и GenerationResultsPage.
Для ручной проверки интерфейса с демонстрационными данными доступна страница
/tests/feedback-preview.html при запуске Vite dev. Это отдельный fixture, он
не входит в production-сборку и не записывает ответы в рабочую БД.
